# 五类实体字段模型精简审计

## 结论

当前演示与运行链路只需要维护“接入、资源标签与防护、字段安全、主体鉴权、资源级访问策略”五类配置。数据目录仍保留分类、来源单位、更新周期和统计字段，因为目录页和统计页仍使用它们；本审计只清理安全管控实体中不参与当前 API 决策的字段。

初始化、迁移和种子脚本现在统一读取 `scripts/security-field-model.mjs`，不会再创建或写入清单中的废弃字段。已有环境可先运行 `node scripts/cleanup-security-fields.mjs` 预览并备份；确认备份后设置 `SECURITY_FIELDS_CLEANUP_APPLY=true` 再执行元数据删列。

## 保留字段

| 实体 | 现行保留字段 | 运行用途 |
| --- | --- | --- |
| 数据源 | 编码、名称、类型、连接状态、责任部门、主机、端口、数据库、用户名、Secret 引用、传输/完整性/抽样配置、校验规则、标签规则、检查摘要 | 连接检查、只读取数、接入校验、标签补全 |
| 数据资源 | 目录基础字段，以及数据源、防护层、资源标签、基准物理表、只读 SQL、SQL 默认参数、资源状态 | 目录展示、标签补全、分类分级、L1/L2/L3 动作、API 发布与查询 |
| 资源字段 | 资源、序号、编码、名称、类型、说明、信息分类、分类层级、安全等级、字段标签、重要字段、要求脱敏、允许 API 返回 | 分类分级详情、标签快照、脱敏、字段输出控制 |
| 数据应用 | 编码、名称、类型、组织、凭据引用、授权 API、IP 白名单、生效区间、状态 | 主体认证、API 授权、来源 IP、有效期校验 |
| 访问策略 | 编码、名称、数据资源、数据应用、API、场景、来源 IP、允许时段、组织/区域范围、频率/时间/行数上限、输出模式、异常规则（启用、允许/拒绝）、版本/发布状态 | 动态策略精确匹配、安全动作、完整版审计日志 |

## 已移出配置入口

| 实体 | 已移除的配置项 | 原因 |
| --- | --- | --- |
| 数据源 | 敏感度、关联安全策略、Workflow、字典反向关系字段 | 当前 API 不读取；来源标签仍由标签规则维护，因此不删除 `source_tags` |
| 数据资源 | 无安全管控专属删项 | 目录页仍使用分类、来源单位、更新周期和统计字段 |
| 资源字段 | 敏感类型、直接/准标识符、定级依据、风险说明、字段访问范围、导出/审批/聚合控制及其字典关系 | 当前动作由字段标签、重要字段、要求脱敏和允许 API 返回覆盖 |
| 数据应用 | API Key 版本、说明 | 不参与认证、授权或策略决策 |
| 访问策略 | 标签组合作用范围、标签选择器、字段白名单、旧审批/导出/API 访问开关及其字典关系 | 统一改为“数据资源 + 数据应用 + API + 场景”精确匹配 |

## 物理删列前提

以下字段仍属于目录或运行链路，不能加入删列清单：资源目录分类/来源/统计字段、数据源 `source_tags`、接入校验和标签规则 JSON、资源安全档案的分类分级与安全标签、访问策略的动态限制和异常规则。物理删列必须同时完成：

1. 导出字段元数据和现有非空数据备份。
2. 删除 NocoBase 字段定义、关联关系和旧页面引用。
3. 更新初始化脚本、种子脚本及回归用例。
4. 执行数据库迁移并运行完整体测试。

当前本机小样本中，所有运行时测试数据均由本表“保留字段”覆盖；因此前端简化不会改变 API 放行、拒绝、脱敏、密态输出或完整版日志行为。
