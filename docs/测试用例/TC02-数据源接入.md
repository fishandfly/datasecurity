# TC02 数据源接入

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC02 |
| 用例名称 | 10 类数据源接入与连接检查 |
| 验证目标 | 验证数据源档案、Secret 引用、真实连接检查、接入通道类型（数据库直连 / 已有 API / E 文件 / 消息服务）与接入日志形成闭环 |
| 对应需求 | 研究内容 1"适配不同来源的数据描述方法、统一数据接入规则"；预期目标"统一数据入口（用采 2.0、调控云等）" |
| 优先级 | 高 |
| 执行角色 | 数据管理员或系统管理员 |
| 测试入口 | `http://localhost:5173/data-catalog/security-governance/ingest/sources` |

## 用户故事

> 作为数据管理员，我希望把用采 2.0、调控云、配电自动化等不同来源的量测数据源统一纳管，并真实检查"连得通"，以便后续资源登记和策略匹配有可信来源。

## 2. 验收范围

1. 10 个种子数据源档案齐全，通道类型覆盖 4 类。
2. 数据源密码不落库、不落表单，仅保存 Secret 引用。
3. 连接检查由安全运行服务真实执行（不 mock）。
4. 成功与失败连接均形成可查询接入日志。
5. 数据源具有来源/数据类型/区域/敏感等级/共享方式五类描述标签。

## 3. 前置条件

- 已完成 TC01（环境与基线就绪）。
- 已登录 `nocobase`。

## 4. 操作步骤

### 步骤 1：查看数据源清单

打开数据源页 `http://localhost:5173/data-catalog/security-governance/ingest/sources`。

预期：列表展示 10 个启用数据源：

| 编码 | 名称 | 通道 |
| --- | --- | --- |
| SRC-YC20-001 | 用采2.0量测数据源 | 数据库直连 |
| SRC-DISPATCH-001 | 调控云量测数据源 | 数据库直连 |
| SRC-EMS-001 | 调度自动化量测数据源 | 数据库直连 |
| SRC-TMR-001 | 电能量计量量测数据源 | 数据库直连 |
| SRC-DISTRIBUTION-001 | 配电自动化量测数据源 | 已有 API |
| SRC-STATION-001 | 新一代集控站量测数据源 | E 文件通道 |
| SRC-DCLOUD-001 | 配电云主站量测数据源 | 消息服务通道 |
| SRC-CABLE-001 | 输变电状态监测量测数据源 | E 文件通道 |
| SRC-WEATHER-001 | 网格化气象预测量测数据源 | E 文件通道 |
| SRC-HVCABLE-001 | 高压电缆在线监测量测数据源 | E 文件通道 |

### 步骤 2：核对 Secret 引用与标签

1. 打开"用采2.0量测数据源"详情。
2. 确认"凭据引用"为 `secret://security/source/src-yc20-001`，页面与数据库均不显示密码明文。
3. 确认五类标签：来源=用采 2.0、数据类型=用户量测、区域=演示区域、敏感度=敏感、共享方式=明细受控。

数据库侧核对（不出现明文密码）：

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT source_code, source_name, connection_status, secret_ref, security_config_json \
   FROM security_data_sources WHERE source_code='SRC-YC20-001'"
```

预期：`connection_status='connected'`，`secret_ref='secret://security/source/src-yc20-001'`，`security_config_json` 只含加密/只读等配置，不含密码明文。

### 步骤 3：执行真实连接检查

1. 在数据源详情页点击"测试连接"。
2. 记录返回结果。

命令行核对（安全运行服务真实执行）：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8196/api/auth:signIn \
  -H 'Content-Type: application/json' \
  -d '{"account":"nocobase","password":"admin123"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')
curl -s -X POST http://127.0.0.1:8090/management/data-sources/1/test \
  -H "Authorization: Bearer $TOKEN" | head -c 300
```

预期：返回成功摘要（含 `latencyMs`），或按实际源类型返回对应结果（E 文件/消息通道返回元数据校验结果）。

### 步骤 4：核对接入日志

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT batch_code, status, started_at FROM security_ingest_logs ORDER BY started_at DESC LIMIT 10"
```

预期：存在真实批次记录（含今天的接入校验批次 `INGEST-2026...`），状态为 `success` 或 `error`。

### 步骤 5：验证失败路径（可选，需管理员配合）

将某源密码改为错误值后测试连接，预期返回失败且生成 `error` 接入日志；恢复原密码后再次测试成功。完成后退回原状。

## 5. 通过标准

- 10 个源档案、4 类通道齐全，名称与客户口径一致（新一代集控站、网格化气象预测等）。
- 无明文密码落库；Secret 引用格式正确。
- 连接检查返回真实结果且形成接入日志。
- 五类标签可读。

## 6. 证据要求

- 数据源列表截图（或 10 源清单）
- 连接测试响应
- 接入日志最近 10 条
- 详情页标签与 Secret 引用截图
