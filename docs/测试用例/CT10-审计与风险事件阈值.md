# CT10 审计日志完整性

## 目标

验证五段证据持久化以及放行、拒绝决策的审计完整性。

## 步骤

1. 执行一次正常脱敏请求、一次时间范围超限、一次行数超限和一次区域越界。
2. 查询审计证据：

```sql
SELECT request_id,decision_result,decision_reason_code,risk_score,
       applied_limits_json->'labelEnrichment',
       applied_limits_json->'classification',
       applied_limits_json->'dynamicPolicy',
       applied_limits_json->'securityActions',
       applied_limits_json->'runtimeTrace'
FROM security_policy_decision_logs WHERE request_id='<请求编号>';
```

3. 确认每个 `request_id` 只对应一条决策日志，且拒绝原因、标签、分类、策略和安全动作均可追溯。

## 预期

正常放行和各类拒绝都只产生一条完整版决策日志。时间范围、行数和区域越界拒绝必须保留各自的原因编码、策略评估和 `DENY` 安全动作；不创建风险事件。通知、人工确认和处置流程不在本用例范围。
