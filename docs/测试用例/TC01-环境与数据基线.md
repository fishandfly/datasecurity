| 项目 | 内容 |

## 用户故事

> 作为验收负责人，我希望先确认环境与数据基线是确定、可复现的，再开始逐项功能验收，避免把环境问题误判为功能缺陷。

## 2. 验收范围

1. 五容器全部健康（frontend / app / postgres / security-runtime / openfhe）。
2. 演示库 `measurement_data` 已初始化（10 张客户对齐物理表 + 基线表）。
3. seed → migrate 幂等重跑通过，migrate 读回验证全绿。
4. 管理端计数达到 3.1 基线（见 README 第 5 节）。
5. 前端首页可登录并展示"数据安全运行链路"与"实时运行监控"三 tab。

## 3. 前置条件

已按 `docker/.env` 配置好 `POSTGRES_PASSWORD`、`SUBJECT_*_SECRET`、`SUBJECT_DEMO_SECRET` 等环境变量。

## 4. 操作步骤

### 步骤 1：检查服务状态

```bash
cd /Users/fish/Documents/FishStudio/AI/2026/012-电网安全-v2.0
docker compose -f docker/docker-compose.yml ps
```

预期：frontend、app、postgres、security-runtime、openfhe 均 `Up` 且 `healthy`；security-runtime 健康接口：

```bash
curl -s http://127.0.0.1:8090/health
```

返回 `"status":"ok"`，且 `configuration` 含 `subjects: 21`、`policies: 62`、`calls: 566` 级别的真实计数。

### 步骤 2：检查演示库表

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d measurement_data -c \
  "SELECT schemaname || '.' || tablename FROM pg_tables WHERE schemaname='measurement_demo' ORDER BY 1"
```

预期：包含 `active_power_measurements` + 10 张客户对齐表：

```text
grid_low_freq_voltage / grid_low_freq_current / grid_low_freq_power / grid_low_freq_power_factor
cust_daily_frozen_energy / cust_measurement_curve / cust_outage_events
grid_switch_events / measurement_no_relad / grid_tmr_energy
```

抽查数据基线（以低频电压为例，应为 1152 行）：

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d measurement_data -c \
  "SELECT COUNT(*) FROM measurement_demo.grid_low_freq_voltage"
```

### 步骤 3：重跑 seed → migrate（验证可复现）

```bash
export NOCOBASE_API_BASE_URL='http://127.0.0.1:8196/api/'
export NOCOBASE_ADMIN_ACCOUNT='admin@nocobase.com'
export NOCOBASE_ADMIN_PASSWORD='admin123'
export NOCOBASE_AUTHENTICATOR='basic'
node scripts/seed-nocobase-demo.mjs

export NOCOBASE_ADMIN_ACCOUNT='nocobase'
node scripts/migrate-nocobase-v3.mjs
```

预期：seed 输出 `resources: 20`（16 启用 + 历史归档）；migrate 输出 `activeResourceCount: 16`，且验证全绿（`missingMetadata: []`、`forbiddenFields: []`、`activeDataSourceCount: 10`）。

### 步骤 4：核对管理端计数

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -t -c \
  "SELECT 'sources', count(*) FROM security_data_sources WHERE connection_status <> 'disabled' \
   UNION ALL SELECT 'resources', count(*) FROM eco_data_resources WHERE resource_status <> 'disabled' \
   UNION ALL SELECT 'subjects', count(*) FROM security_access_subjects WHERE subject_status='enabled' \
   UNION ALL SELECT 'apis', count(*) FROM security_api_resources \
   UNION ALL SELECT 'policies', count(*) FROM eco_resource_security_policies \
   UNION ALL SELECT 'keys', count(*) FROM security_crypto_keys WHERE key_status='enabled'"
```

预期：`sources=10`、`resources=16`、`subjects=21`、`apis=20`、`policies=83`、`keys=16`。

### 步骤 5：前端登录与首页检查

1. 打开 `http://localhost:5173/data-catalog/`。
2. 使用 `nocobase` / `admin123` 登录。
3. 确认首页顶部为"数据安全运行链路"，其下为"实时运行监控"三 tab（实时运行情况 / 分层策略流转 / 同态加密流转）。
4. 确认链路卡片显示真实计数（数据源 10、资源 API 20、启用策略 62、访问调用 566 级）。

## 5. 通过标准

- 五容器健康，`/health` 返回 ok 且计数与基线一致。
- 演示库 11 张表齐全，抽样表行数与种子规格一致。
- seed→migrate 幂等通过，migrate 读回验证无缺失/无违规字段。
- 管理端六项计数与基线一致。
- 首页结构与三 tab 正常渲染。
