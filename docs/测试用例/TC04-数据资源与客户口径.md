# TC04 数据资源登记与客户口径

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC04 |
| 用例名称 | 数据资源登记、字段与客户分类口径 |
| 验证目标 | 验证 16 个资源档案（客户名称/编码/字段/防护层/关联状态）、客户分类树挂接与申请热度回填 |
| 对应需求 | 研究内容 2"对不同类型和不同敏感级别的数据进行分层隔离"；预期目标"数据描述标签标注" |
| 优先级 | 高 |
| 执行角色 | 数据管理员或安全管理员 |
| 测试入口 | `http://localhost:5173/data-catalog/security-governance/resources` |

## 用户故事

> 作为数据管理员，我希望资源名称、字段与分类都按客户口径统一（低频电压、日冻结、电能示值曲线等），并标注申请热度，让"数据资源"列在监控和审批中一目了然。

## 2. 验收范围

1. 16 个启用资源齐全，名称为客户口径。
2. 分类树挂接正确（采集/负荷/电量/事件类）。
3. 防护层 l1/l2/l3 与资源敏感度匹配。
4. 字段定义与客户字段级明细一致（含直接标识符、准标识符标注）。
5. `usage_count` 申请热度按客户次数回填。
6. 关联状态（`linked`/`unlinked`）正确。

## 3. 前置条件

- 已完成 TC01。
- 已登录 `nocobase`。

## 4. 操作步骤

docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \

### 步骤 2：核对分类挂接

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT r.resource_code, c.\"nodeName\" AS category FROM eco_data_resources r \
   JOIN \"jcCategoryTreeNodes\" c ON c.id = r.domain_category_id \
   WHERE r.resource_status <> 'disabled' ORDER BY r.display_seq"
```

预期分类（客户口径）：

| 资源 | 分类 |
| --- | --- |
| 低频电压/电流/功率曲线、电能示值曲线、高压日负荷 | 负荷类 |
| 日冻结、主网电能示值、高压/低压日用能信息 | 电量类 |
| 功率因数、未关联归档、相位角曲线、用户侧负荷曲线、调度实时量测 | 采集类 |
| 用户停复电、开关变位 | 事件类 |

### 步骤 3：核对字段与敏感标注

打开"日冻结电能示值"详情 → "资源字段"。

预期：

- 字段含 `DATA_DATE`、`CONS_NO`（用户标识）、`METER_DEV_ID`（电能表标识）、`POS_CODE`、`PAP_R`（正向有功总电能示值）等。
- `CONS_NO` 标注 直接标识符 + 准标识符 + 脱敏方式 `tokenize`；`PAP_R` 标注 仅聚合（`aggregate-only`）。

### 步骤 4：核对申请热度

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT resource_code, resource_name, usage_count FROM eco_data_resources \
   WHERE resource_status <> 'disabled' AND usage_count IS NOT NULL ORDER BY usage_count DESC LIMIT 8"
```

预期 TOP：低频电压 22、低频电流 20、日冻结 18、低频功率 18、电能示值曲线 14、功率因数 12、相位角 9、高压日用能 9。

### 步骤 5：手工新建资源教学流程（可选）

1. 资源页点"新建数据资源"（位于检索按钮右侧）。
2. 填写编码（如 `RES-MEASURE-001`）、名称（业务化，禁止客户真实表名）、来源系统、基准物理表 `measurement_demo.active_power_measurements`、防护层 l2、8 个基础字段（`DATA_TIME/POINT_CODE/MEASURE_TYPE/EQUIP_TYPE/SAMPLE_INTERVAL/U_A/U_B/U_C/QUALITY_CODE` 或按实际）。
3. 保存后确认自动生成唯一 API `API-RES-MEASURE-001`（草稿）。

> 注意：重跑 migrate 会把手工资源归档为"历史归档"，正式验收时在 TC 执行完成后不再重跑 migrate。

## 5. 通过标准

- 16 个资源名称/防护层/关联状态与清单一致。
- 分类挂接与客户 6 类口径一致（16 个资源覆盖采集/负荷/电量/事件 4 类）。
- 字段敏感标注（标识符/仅聚合）正确。
- 热度 TOP 与客户申请次数一致。
- 手工新建资源流程可走通并自动生成默认 API。

## 6. 证据要求

- 资源清单与分类 SQL 输出
- 字段敏感标注截图
- 热度 TOP 输出
- 手工新建资源与自动 API 截图（若执行步骤 5）
