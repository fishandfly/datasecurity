# TC09 跨域密态计算

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC09 |
| 用例名称 | 基于同态加密的跨域密态计算 |
| 验证目标 | 验证 BFV（整数）/ CKKS（浮点）密态计算、任务生命周期、结果校验、明文不落库 |
| 对应需求 | 研究内容 3"跨域密态计算方法，量测数据可用不可见"；预期目标"同态加密跨域密态计算" |
| 优先级 | 高 |
| 执行角色 | 安全管理员 / 应用负责人 |
| 测试入口 | `http://localhost:5173/data-catalog/security-governance/...`（密态任务）与 `/data-api` 调用 |

## 用户故事

> 作为应用负责人，我希望在授权范围内对量测数据做"可用不可见"的统计计算（求和/均值），全程不接触用户级明文，并能在任务记录中核验计算结果。

## 2. 验收范围

1. 整数精确型（BFV）：日冻结 `PAP_R` 求和，`absoluteError=0`。
2. 浮点近似型（CKKS）：低频电压 `VOLTAGE` 均值（含 `scales` 缩放）。
3. 密态任务自动创建并完成，`sample_count` 与授权范围一致。
4. 任务记录不含明文数值数组（`has_values=false`、无 `forbiddenPayload`）。
5. 结果校验 `verificationPassed=true`。
6. 未授权主体/无密钥主体无法执行密态计算。

## 3. 前置条件

- 已完成 TC01、TC06。
- openfhe 服务健康：`curl -s http://127.0.0.1:8088/health` 返回 `algorithms: ["BFV","CKKS"]`。
- 密态客户主体（营销 2.0、售电量预测、电力看信用、电力看环保、数字化供电所、充换电、智能供服）已分配 BFV/CKKS 演示密钥。

## 4. 操作步骤

### 步骤 1：验证 BFV 整数密态（日冻结求和）

```bash
cd /Users/fish/Documents/FishStudio/AI/2026/012-电网安全-v2.0
SECRET=$(grep '^SUBJECT_DEMO_SECRET=' docker/.env | cut -d= -f2)
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/cust-daily-energy-003?operation=sum&fieldCode=PAP_R&regionCode=REGION-A&startAt=2026-06-25T00%3A00%3A00%2B08%3A00&endAt=2026-06-26T00%3A00%3A00%2B08%3A00" \
  APP-MARKETING-2 marketing-2-daily-energy
```

预期：HTTP 200；响应含 `algorithm: BFV`、`resultSummary.verificationPassed=true`、`absoluteError=0`。

### 步骤 2：验证 CKKS 浮点密态（电能示值曲线均值）

```bash
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/cust-power-curve-005?operation=mean&fieldCode=VALUE&regionCode=REGION-A&startAt=2026-07-01T08%3A00%3A00%2B08%3A00&endAt=2026-07-01T09%3A00%3A00%2B08%3A00" \
  APP-MARKETING-2 marketing-2-energy-curve
```

预期：HTTP 200，`algorithm: CKKS`，结果校验通过；`VALUE` 为浮点量测值，走浮点近似型密态计算。

> 变体（可选）：若需验证 `scales` 缩放，可临时为某主体授权低频电压密态策略后，对 `grid-lvf-volt-001` / `VOLTAGE` 执行 `mean`，结果按档案 `scales={VOLTAGE:0.001}` 缩放。

### 步骤 3：核对任务记录与明文隔离

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT task_code, task_status, algorithm, operation, sample_count \
   FROM security_confidential_tasks ORDER BY id DESC LIMIT 6"

docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -t -c \
  "SELECT jsonb_pretty(execution_summary_json->'logs') \
   FROM security_confidential_tasks WHERE task_status='completed' ORDER BY id DESC LIMIT 1"
```

预期：最近任务 `completed`、`sample_count>0`；任务日志阶段链为 `created → validation → resource_read → compute → result`，其中 compute 阶段消息为"原始数值已在内存中提交密态计算，不写入任务记录"（明文数组不落库）。

### 步骤 4：验证无密钥主体拒绝

对未分配密钥的主体（如"网上电网应用"，masked 策略）发起密态参数请求：


预期：因策略不匹配返回 `POLICY_NOT_FOUND`（或对应拒绝），不会执行密态计算。

- BFV/CKKS 均返回校验通过结果（BFV 绝对误差 0、CKKS 容差内）。
- 任务记录明文不落库。
- 无密钥/未授权主体无法执行密态计算。
- 页面任务可查且结果摘要真实。
