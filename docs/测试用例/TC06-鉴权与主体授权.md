# TC06 鉴权与主体授权

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC06 |
| 用例名称 | 主体鉴权（API Key/HMAC）与 API 授权 |
| 验证目标 | 验证 21 个主体的凭据认证、状态/有效期、API 授权清单闭环，并覆盖错误密钥、主体停用、未授权等失败路径 |
| 对应需求 | 研究内容 2"综合参考用户角色、数据类型、场景条件因素的多因素访问控制"的认证前提 |
| 优先级 | 高 |
| 执行角色 | 安全管理员 |
| 测试入口 | `http://localhost:5173/data-catalog/security-governance/access/subjects` |

## 用户故事

> 作为安全管理员，我希望每个数据应用凭据可识别、状态可控、授权清单可查，保证只有被授权的应用才能进入策略决策阶段。

## 2. 验收范围

1. 21 个主体（3 基线 + 18 客户应用）启用，凭据引用不落明文。
2. 有效凭据可精确识别主体（HMAC access-key 或唯一 API Key）。
3. 错误密钥 → `API_KEY_INVALID` / `SIGNATURE_INVALID`。
4. 主体停用 → `SUBJECT_DISABLED`；恢复启用 → 可访问。
5. 主体未授权某 API → `API_NOT_AUTHORIZED`。
6. 授权后进入策略阶段（由 TC07 覆盖）。

## 3. 前置条件

- 已完成 TC01、TC05。
- `docker/.env` 中 `SUBJECT_DEMO_SECRET` 已配置（18 个客户主体共享演示凭据，HMAC access-key 精确指定主体）。

## 4. 操作步骤

### 步骤 1：核对主体清单

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT subject_code, subject_name, subject_status, credential_ref FROM security_access_subjects ORDER BY id"
```

预期：21 条启用主体；客户应用名称与 7 专业对应（网上电网、能源互联网营销、一体化电量线损、线变关系、售电量预测、电力看信用、数据质量核查、数据传输、全链路监控、智慧城市、多源平台、数字化供电所、充换电、新能源选址、数字化审计、纪检、智能供服等）。

### 步骤 2：正确凭据调用（HMAC）

```bash
cd /Users/fish/Documents/FishStudio/AI/2026/012-电网安全-v2.0
SECRET=$(grep '^SUBJECT_DEMO_SECRET=' docker/.env | cut -d= -f2)
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?pageSize=3" \
  APP-ONLINE-GRID online-grid-lvf-voltage
```

预期：HTTP 200，决策 `allow`。

### 步骤 3：错误密钥

```bash
SUBJECT_SECRET="$(printf 'a%.0s' {1..40})" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?pageSize=3" \
  APP-ONLINE-GRID online-grid-lvf-voltage
```

预期：HTTP 403 `SIGNATURE_INVALID`（若使用 API Key 模式则为 401 `API_KEY_INVALID`）。

### 步骤 4：主体停用与恢复

1. 管理端将"网上电网应用"主体停用。
2. 重复步骤 2，预期 HTTP 403 `SUBJECT_DISABLED`。
3. 恢复启用，重复步骤 2，预期恢复 200。

### 步骤 5：未授权 API

1. 临时移除"网上电网应用"对 `API-GRID-LVF-VOLT-001` 的授权（管理端授权清单）。
2. 重复步骤 2，预期 HTTP 403 `API_NOT_AUTHORIZED`。
3. 恢复授权，预期 200。

### 步骤 6：核对授权清单落库

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT subject_code, allowed_api_codes_json FROM security_access_subjects WHERE subject_code='APP-ONLINE-GRID'"
```

预期：授权清单含低频电压/电流/功率/相位角 4 个 API 编码。

## 5. 通过标准

- 21 主体启用、凭据引用规范、无明文密钥。
- 正确凭据 200、错误密钥、停用、未授权均返回对应原因编码。
- 恢复操作后访问正常。

## 6. 证据要求

- 主体清单 SQL 输出
- 四种鉴权结果响应（200 / 401 / 403 各阶段）
- 授权清单 SQL 输出
