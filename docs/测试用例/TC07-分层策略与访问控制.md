# TC07 分层策略与访问控制

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC07 |
| 用例名称 | 分层防护（l1/l2/l3）与多因素访问控制 |
| 验证目标 | 验证资源防护层、输出模式（明细/脱敏/聚合/密态）、多因素条件（场景/IP/区域/时间）与策略命中/拒绝闭环 |
| 对应需求 | 研究内容 2"不同类型和不同敏感级别的数据分层隔离""多因素条件访问控制" |
| 优先级 | 高 |
| 执行角色 | 安全管理员 |
| 测试入口 | 资源详情 → 访问策略；`http://127.0.0.1:8090/data-api/...` |

## 用户故事

> 作为安全管理员，我希望数据按敏感级别进入不同防护层（l1 仅聚合、l2 明细受控、l3 仅密态），并综合应用、场景、IP、区域条件决定放行或拒绝。

## 2. 验收范围

1. 三类防护层 l1/l2/l3 与资源对应关系正确。
2. 四类输出模式（明细/脱敏/聚合/密态）分别由对应策略命中。
3. 多因素条件：场景匹配、区域范围（`region_scope_json`）、时间窗口、IP 白名单。
4. 标签硬约束（如 `aggregateOnly`/`encryptedOnly`）与策略输出模式一致性校验。
5. 放行与拒绝均形成决策日志。

## 3. 前置条件

- 已完成 TC01、TC06。

## 4. 操作步骤

### 步骤 1：核对防护层与输出模式分布

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT protection_level, count(*) FROM eco_data_resources WHERE resource_status <> 'disabled' GROUP BY 1 ORDER BY 1"
```

预期：l1=3、l2=7、l3=6（低频功率因数/调度实时/未关联归档为 l1；用户侧负荷/低频电压/电流/功率/开关事件/主网电能示值/相位角为 l2；日冻结/电能示值曲线/停复电/高压日用能/低压日用能/高压日负荷为 l3）。

### 步骤 2：核对策略命中（脱敏输出示例）

网上电网 → 低频电压（`output_mode=masked`）：

```bash
cd /Users/fish/Documents/FishStudio/AI/2026/012-电网安全-v2.0
SECRET=$(grep '^SUBJECT_DEMO_SECRET=' docker/.env | cut -d= -f2)
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?pageSize=3" \
  APP-ONLINE-GRID online-grid-lvf-voltage
```

预期：HTTP 200，`outputMode=masked`，设备标识脱敏（`PSR***`）。

### 步骤 3：核对聚合输出

智慧城市 → 低频电压（`output_mode=aggregate`）：

```bash
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?regionCode=REGION-A&startAt=2026-07-01T00%3A00%3A00%2B08%3A00&endAt=2026-07-01T04%3A00%3A00%2B08%3A00&metric=VOLTAGE" \
  APP-SMART-CITY smart-city-volt
```

预期：HTTP 200，返回按小时聚合结果（`sum/average/sampleCount`），`outputMode=aggregate`。

### 步骤 4：核对密态输出

营销 2.0 → 日冻结（`output_mode=encrypted`）：

```bash
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \

  APP-MARKETING-2 marketing-2-daily-energy
```

预期：HTTP 200，返回密态结果摘要（`resultSummary`），并自动创建同态任务。

### 步骤 5：核对场景不匹配拒绝

使用错误场景调用（主体存在、API 存在、策略 scenario 不匹配）：

```bash
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?pageSize=3" \
  APP-ONLINE-GRID wrong-scenario
```

预期：HTTP 403 `POLICY_NOT_FOUND`。

### 步骤 6：核对标签硬约束

对 `GRID-NO-RELAD-009`（l1 仅聚合、标签 `aggregateOnly`）发起明细请求，预期拒绝并给出标签约束原因（`TAG_CONSTRAINT_VIOLATION` 或按策略输出模式校验结果）。

## 5. 通过标准

- 防护层计数与资源口径一致。
- masked/aggregate/encrypted 三种输出均返回正确结果与决策日志。
- 场景不匹配返回 `POLICY_NOT_FOUND`。
- 标签硬约束生效。

## 6. 证据要求

- 防护层分布 SQL
- 三种输出调用响应
- 拒绝响应（含 requestId、原因编码）
- 对应决策日志查询
