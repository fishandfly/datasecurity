# TC12 客户数据对齐与红线核查

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC12 |
| 用例名称 | 客户数据模拟对齐与红线合规核查 |
| 验证目标 | 验证演示数据与客户资料对齐（资源/源/应用命名、分类、热度、未关联来源），且不暴露客户真实表名与真实规模 |
| 对应需求 | 客户资料（`docs/data/`）与项目红线：不出现 `EMS_*`/`rmc_*` 真实表名、不出现 215TB/153 表真实规模 |

## 用户故事

> 作为项目负责人，我希望演示数据说的清"来自客户的哪些业务"，同时不泄露客户真实系统名、表名和规模，保证对外演示安全合规。

## 2. 验收范围

1. 资源名/源名/应用名为客户口径（业务化），无客户真实表名。
2. 分类树与客户 6 类口径一致；16 个资源挂接正确。
3. 申请热度与客户申请次数一致。
4. "未关联量测归档"来源可解释（客户 `*_NO_RELAD` 三类未关联表的汇总模拟）。
5. UI 与数据库无客户真实表名（`EMS_*`、`rmc_*`）、无真实规模（215TB/153 表/4600 亿条）字样。
6. 演示数据可复现（seed→migrate 确定性生成）。

## 3. 前置条件

- 已完成 TC01-TC11。

### 步骤 2：分类与热度核对

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT r.resource_code, c.\"nodeName\", r.usage_count FROM eco_data_resources r \
   JOIN \"jcCategoryTreeNodes\" c ON c.id = r.domain_category_id \
   WHERE r.resource_status <> 'disabled' ORDER BY r.usage_count DESC NULLS LAST LIMIT 10"
```

预期：低频电压 22（负荷类）、低频电流 20（负荷类）、日冻结 18（电量类）、低频功率 18（负荷类）、电能示值曲线 14（负荷类）、功率因数 12（采集类）、相位角 9（采集类）、高压日用能 9（电量类）等。

### 步骤 3：未关联量测来源解释

1. 打开"未关联量测归档"资源详情。
2. 核对说明：来源为"历史量测中心"，语义为客户附件一 `*_NO_RELAD` 表（EMS/DMS/CMS 三类未关联遥测/遥信/电能示值/日冻结）的汇总模拟；`link_status=unlinked`、防护层 l1 仅聚合。

### 步骤 4：红线扫描

```bash
cd /Users/fish/Documents/FishStudio/AI/2026/012-电网安全-v2.0
rg -n "EMS_[A-Z_]+|rmc_[A-Z_]+|215\s*TB|153\s*表|4600\s*多亿" src/ --glob '!*.test.mjs' || echo "UI 无红线命中"
```

预期：`src/` 下无客户真实表名/真实规模字样（测试文件除外）。

数据库侧核对（管理库不得出现客户真实表名作为资源来源表）：

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -t -c \
  "SELECT count(*) FROM eco_data_resources WHERE source_table ~ 'EMS_|rmc_'"
```

预期：0。

### 步骤 5：可复现性

重跑 `seed → migrate`（命令见 TC01 步骤 3），确认计数回到基线且无报错。

## 5. 通过标准

- 未关联归档语义可解释。
- UI 与数据库无红线命中。
- seed→migrate 确定性复现。
