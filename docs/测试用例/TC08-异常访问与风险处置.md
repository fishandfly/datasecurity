# TC08 异常访问与风险处置

## 1. 用例信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | TC08 |
| 用例名称 | 异常访问识别与风险事件处置 |
| 验证目标 | 验证查询范围/行数/时段/频率等异常规则触发拒绝、风险事件生成与处置闭环 |
| 对应需求 | 研究内容 2"通过规则/模型识别越权访问、非正常数据调用等风险" |
| 优先级 | 高 |
| 执行角色 | 安全运营人员 |
| 测试入口 | `http://localhost:5173/data-catalog/` → 风险事件 |

## 用户故事

> 作为安全运营人员，我希望非正常调用（跨范围、超行数、非工作时段、高频）被策略引擎识别并拒绝，同时生成可处置的风险事件，形成"识别-拒绝-处置"闭环。

## 2. 验收范围

1. 异常规则（`abnormal_access_rules_json`）覆盖 范围/行数/时段/频率。
2. 触发规则后返回对应原因编码并写入 deny 决策日志。
3. `risk_score ≥ 70` 的拒绝自动生成风险事件。
4. 风险事件可在页面查看、处置（处置后状态变化）。
5. 明细列表明细均来自真实决策日志。

## 3. 前置条件

- 已完成 TC01、TC06、TC07。

## 4. 操作步骤

### 步骤 1：核对异常规则落库

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT policy_code, abnormal_access_rules_json FROM eco_resource_security_policies \
   WHERE policy_code='V3-POL-ONLINE-GRID-VOLT'"
```

预期：规则含 `queryRangeExceeded`（score 60）、`rowLimitExceeded`（70）、`offHours`（70）、`highFrequency`（70）、`scopeViolation`（80）、`behaviorAnomaly`（20）。

### 步骤 2：触发查询范围超限

策略 `max_query_days=7`，请求 30 天跨度：

```bash
cd /Users/fish/Documents/FishStudio/AI/2026/012-电网安全-v2.0
SECRET=$(grep '^SUBJECT_DEMO_SECRET=' docker/.env | cut -d= -f2)
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?pageSize=3&startAt=2026-06-01T00%3A00%3A00%2B08%3A00&endAt=2026-07-01T00%3A00%3A00%2B08%3A00" \
  APP-ONLINE-GRID online-grid-lvf-voltage
```

预期：HTTP 422 `QUERY_RANGE_EXCEEDED`，决策日志 `deny`。

### 步骤 3：触发行数超限

请求 `pageSize=5000`（策略 `max_rows=1000`）：

```bash
SUBJECT_SECRET="$SECRET" API_AUTH_MODE=hmac node scripts/call-v3-data-api.mjs \
  "http://127.0.0.1:8090/data-api/resources/grid-lvf-volt-001?pageSize=5000" \
  APP-ONLINE-GRID online-grid-lvf-voltage
```

预期：HTTP 422 `ROW_LIMIT_EXCEEDED`（或按策略返回对应编码），决策日志 `deny`。

### 步骤 4：核对风险事件生成

```bash
docker exec nocobase-8196-postgres-1 psql -U nocobase -d nocobase -c \
  "SELECT event_code, risk_type, risk_score, risk_level, event_status, decision_log_id \
   FROM security_risk_events ORDER BY \"createdAt\" DESC LIMIT 5"
```

预期：存在与刚才 `QUERY_RANGE_EXCEEDED`/`ROW_LIMIT_EXCEEDED` 对应的风险事件（`risk_score≥70`），`event_status='pending'`。

### 步骤 5：页面处置风险事件

1. 打开首页"风险事件"入口（或导航"风险事件"）。
2. 打开一条待处置事件，执行"标记处置"。
3. 预期：事件状态由 `pending` 变为处置状态，列表更新。

### 步骤 6：核对异常分析真实性

首页"实时运行情况"tab 的"访问异常分析"应展示真实统计（来自 `security_risk_events` 与 `security_policy_decision_logs`），无固定假数据。

## 5. 通过标准

- 异常规则完整落库。
- 范围/行数超限触发真实拒绝并生成决策日志。
- 高风险拒绝自动生成风险事件。
- 风险事件可处置且状态流转。
- 异常分析与事件流来自真实数据。

## 6. 证据要求

- 异常规则 SQL 输出
- 两种拒绝响应（requestId + 原因编码）
- deny 决策日志与风险事件 SQL
- 风险处置前后截图
